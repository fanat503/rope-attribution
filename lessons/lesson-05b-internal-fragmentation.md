# Урок 05Б — Пустое место внутри отданной области

**Статус:** текущий короткий урок  
**Время:** 8–12 минут  
**Предпосылка:** Lesson 05A пройден  
**Цель:** понять только внутреннюю фрагментацию; внешнюю пока не рассматриваем

---

## 1. Новое название для уже понятной величины

В прошлом уроке мы различили:

1. место с данными K/V;
2. пустое место, уже обещанное запросам;
3. действительно свободное место.

Теперь даём второму пункту техническое название:

> **Внутренняя фрагментация** — пустое место внутри областей памяти, уже отданных запросам.

Почему «внутренняя»: это место находится **внутри** выделенной области конкретного запроса.

---

## 2. Состояние одного запроса

Для текущей темы достаточно трёх чисел:

```text
начало       — где начинается область запроса;
вместимость  — сколько ячеек ему отдано;
длина        — сколько ячеек уже содержат K/V.
```

Обязательное условие:

```text
0 <= длина <= вместимость
```

Пустое обещанное место этого запроса:

```text
внутренняя_фрагментация = вместимость - длина
```

Поле `начало` для этой формулы не требуется, но позже оно понадобится, чтобы найти физический адрес K/V.

---

## 3. Откуда появляется это место

При autoregressive decode окончательная длина ответа заранее неизвестна.

Если системе нужен один непрерывный участок KV cache, она может заранее отдать запросу область с запасом:

```text
отдано 12 ячеек
K/V записаны в 5
```

Тогда:

```text
12 - 5 = 7
```

Семь ячеек пока пусты, но другой запрос не может их занять.

По мере генерации `длина` растёт, поэтому пустой остаток может уменьшаться. После завершения запроса вся его область освобождается.

---

## 4. Несколько запросов

Для нескольких запросов внутренняя фрагментация складывается:

```text
общая_внутренняя_фрагментация
= сумма(вместимость запроса - длина запроса)
```

### Пример

Всего в памяти `24` ячейки.

```text
Запрос А: отдано 10, с данными 6
Запрос Б: отдано 8,  с данными 5
```

Место с данными:

```text
6 + 5 = 11
```

Всё отданное место:

```text
10 + 8 = 18
```

Внутренняя фрагментация:

```text
(10 - 6) + (8 - 5)
= 4 + 3
= 7
```

Действительно свободно:

```text
24 - 18 = 6
```

Проверка всей памяти:

```text
11 с данными + 7 пустых обещанных + 6 свободных = 24
```

---

## 5. Почему нельзя просто не оставлять запас

Если всегда отдавать запросу ровно столько места, сколько он уже заполнил, следующий token может не поместиться рядом: сразу после области может находиться другой запрос.

Тогда придётся:

1. найти новый больший непрерывный участок;
2. скопировать туда все старые K/V;
3. освободить старую область.

Значит, предварительный запас меняет одну проблему на другую:

```text
большой запас  -> пустое обещанное место
маленький запас -> возможные переносы растущего KV cache
```

Paged KV cache позже ослабит эту дилемму: запрос сможет получать небольшие blocks по мере роста, не требуя одного большого непрерывного участка.

---

## 6. Короткая проверка

Всего в памяти `30` ячеек.

```text
Запрос А: отдано 12, с данными 7
Запрос Б: отдано 9,  с данными 4
```

Ответьте тремя числами:

1. Сколько ячеек содержат K/V?
2. Какова общая внутренняя фрагментация?
3. Сколько ячеек действительно свободны?

И одной короткой фразой:

4. Почему пустые ячейки внутренней фрагментации нельзя отдать третьему запросу?

## Необязательный словарь

```text
вместимость              = capacity
длина                     = length
внутренняя фрагментация   = internal fragmentation
```
