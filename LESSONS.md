# Distilled lessons — harness design for coding agents

Source: Fan et al., *An Empirical Study of Harness Design for Coding Agents*,
arXiv:2609.20804 (UMass Amherst / Emory / UNC Charlotte / Zoom, 43 pages,
Sep 2026). Read in full on 2026-10-11; every claim below is one that paper
reports, and each is annotated with what it means **for this repository**.

The paper's method is the part worth copying, not its numbers. They fixed the
execution loop and varied exactly three components — planning, action space,
context management — across 176 matched settings, then used trajectory-level
annotation to explain *why* each intervention moved the result. Four models, two
benchmarks, five context tiers, four window budgets.

---

## 1. Ablate one component at a time, with everything else pinned

They held the ReAct loop, the safety gates, the diagnostics and the stuck
detector fixed, and varied one component. That is what made the effect
*attributable* rather than merely observed.

**Here:** the repository already does this for the science — `experiments.py`
varies one quantity per experiment and records the grid. What it has never done
is ablate its own harness. The claim "26.8% of cells get the wrong sign" is an
aggregate over three checkpoints, 2790 heads and 13 distances. It has no
uncertainty attached, so a reader cannot tell whether it is 26.8% ± 0.1 or
± 8. See `statistics.py`'s seed-variance block for the only place in this repo
that quantifies spread at all.

**Action:** `usefulness.bootstrap_ci()` (added) reports percentile bootstrap
intervals for the headline aggregate, and a per-checkpoint agreement test, so the
paper's central number carries an interval.

## 2. Match the comparison, then test it — do not eyeball it

Every comparison in the paper is task-paired, tested with a two-sided exact
McNemar test, and the family of comparisons is controlled with
Benjamini–Hochberg at q < 0.05. They report significance per cell rather than
comparing means.

**Here:** the paper reports `27.6% / 26.3% / 26.4%` across three checkpoints and
`22.4%–34.9%` across heads, with no statement of whether the three agree beyond
pointing at the numbers. Three numbers that look alike are not evidence that they
are alike.

**Action:** `test_the_three_checkpoints_agree_on_the_rate` is a paired
permutation test over heads; it fails if any checkpoint disagrees.

## 3. Cheap-and-lossy beats expensive; do not build machinery nothing uses

Their strongest practical result: staging elision before LLM summarization gave
the best accuracy–cost profile, because the cheap mechanism resolved most cases
before the expensive one ran. And the *lossless* recall machinery — external
storage plus a `recall_event` tool — was invoked in 56.3% of settings never at
all, and conferred no accuracy gain over elision alone across 32 matched
comparisons. They built it, measured it, and reported that it was not worth
having.

**Here:** `results/usefulness_grid_independence.json` was exactly that machinery.
Nothing referenced it, no test regenerated it, and its schema did not match what
`usefulness.grid_independence()` wrote. It existed because it seemed like it
ought to. It is now generated by `usefulness.main()`, self-describing, and
covered by three tests that fail if it goes stale — which is the version of
"build it" that survives this paper's finding.

## 4. An intervention's value is conditional, not universal

Planning was an accuracy scaffold for the weakest model (+11.6 points) and a cost
saver for the strongest (−30% cost at −2.0 points accuracy). Neither
characterisation is "planning is good". The paper's title characterisation —
"model- and budget-aware harness design" — is the honest one.

**Here:** the paper's claim "context extension is geometrically favourable" is
already qualified per-scheme in `tab:spectrum`, which is right. The place it is
*not* qualified is the sign-reversal claim, which is stated unconditionally —
and the 12-seed sweep in `figures.fig10` is what licenses that. Keep that
distinction: measured unconditional, versus asserted conditional.

## 5. Return errors as observations, never as exceptions

A failed action in their harness is appended to the history as an observation so
the loop continues and the model can recover. A crash ends the run.

**Here:** `Makefile`'s `paper` target falls back from `tectonic` on `PATH` to
`.tmp/tectonic/tectonic.exe`, so a missing binary is a different message rather
than a dead target. `usefulness.py` and `real_model.py` raise with a sentence
saying what to install. Good — this is already the pattern.

## 6. Run a fast read-only check immediately after every edit

After an edit they run ruff/pyflakes/syntax-only and append the findings to the
tool result, so a syntax error is visible in the same turn instead of costing a
turn to discover.

**Here:** ruff is run at the end of a batch, not after each edit, which is why a
`NameError` sat in `figures.py` through two commits. `make postedit` now runs
ruff plus the affected module's own tests immediately; see §7.

## 7. Mistakes this session made repeatedly, and the guard for each

These are my own, from this repository's session history. They are recorded
because a lesson that is not a check is a lecture.

| # | mistake | times | guard |
|---|---|---|---|
| 1 | Assumed `$env:ROOT` survived between shell calls — it does not; every call is a fresh process | 3 | set `$env:ROOT = (Get-Location).Path` **first**, every command |
| 2 | Typed a Cyrillic literal into a command line; the console mangled it to `C:\Users\????` | 4 | never type the path; always derive it |
| 3 | `write`/`edit` silently targeted `Проект по умолчание` (typo) instead of `Проект по умолчанию` | 2 | verify the destination exists and parses after writing; `write` to a `.tmp` script and run it instead |
| 4 | `git add -u` staged nothing new, so a figure the paper cites was absent from the commit | 1 | `git status --short` after `git add`; count untracked entries |
| 5 | Called `ast.parse()` on TOML / YAML / BibTeX and reported the resulting SyntaxError as a finding | 3 | only `ast.parse` a `.py`; validate TOML with `tomllib`, YAML with `yaml` |
| 6 | Wrote `pathlib.Path("...")` with a stray closing paren, then blamed the heredoc | 3 | read the traceback's line number back before theorising |
| 7 | Wrote a guard that passed on the defective input, i.e. vacuous | 2 | `teeth.py`: deliberately reintroduce the defect and assert the guard fails |
| 8 | Added `Co-Authored-By: Claude` while writing the commit message that removed it | 1 | `tests/test_authorship.py` now scans every ref; check the message before `git commit` |
| 9 | Compared a fraction against a percentage and called the failure a bug in the data | 1 | unit-mismatch check first, before touching the artefact |

Item 7 is the one that matters most and is the paper's methodological point in
miniature: a guard that cannot fail is not a guard, and the cost of discovering
it is paid by whoever reads the result later.
